# COMMON FOUNDATION (sab modules pe lagu)

**Common rules:** API prefix `/api/scm/...`. Har create/edit/action `audit_log` mein jayega. Har master `effective_from/effective_to` aur `status[draft/active/disabled]` ke saath hoga (delete nahi, disable). Har table mein `entity_id` aur jahan relevant ho `site_id` hoga (multi-company, multi-site). Policy, threshold, rate, tolerance aur horizon **config tables** mein rahenge, hardcode nahi. Har POST pe `idempotency_key`, har edit pe `version` (optimistic locking).

- **Event-driven core:** inventory move, shipment milestone, production confirmation, quality result, PO change sab `scm_events` pe jayenge (idempotent, replayable). Planning, visibility aur alerts isi se chalte hain.
- **Scenario/Version engine:** koi bhi plan (demand, supply, MPS, DRP, network) `planning_versions` aur `scenarios` mein banega. Baseline lock, what-if copy, side-by-side compare, aur approved scenario ko "publish to execution" kar sakte hain.
- **Exception engine:** har module ka alert (late PO, stockout risk, SLA breach, quality hold) ek jagah `exceptions` mein, owner, severity, SLA, auto-assign, aur resolution workflow ke saath.
- **AI guardrail:** AI jo bhi recommend kare (forecast override, reorder, route, supplier pick) `ai_decisions` mein save hoga: input, output, confidence, explanation. Execute karne se pehle human approval (config se auto-approve limit).
- **Planning buckets/horizons:** daily/weekly/monthly buckets, horizon (operational / tactical / strategic) config se.
- **As-of date reporting:** koi bhi report past/current/future date se chalti hai.
- **Multi-country:** currency + base-currency conversion, UoM conversion, tax config (GST e-way bill/e-invoice, VAT), customs aur labeling rules `country_config` se.
- **Multi-language:** SOP, label, notification, portal text `translations` se.
- **Mobile/offline:** warehouse RF, shop-floor terminal, driver app offline chalenge aur sync pe conflict resolve.
- **Access:** role + ABAC (site, category, supplier, confidential contracts ke hisaab se data scope).

### Core Logic
1. Final forecast = statistical + approved overrides. Har override reason code ke saath aur FVA se measure hota hai (override ne accuracy badhayi ya bigaadi).
2. History mein stockout wale periods ka demand cleanse hota hai, warna forecast neeche chala jata hai.
3. Hierarchy reconciliation: lower-level forecasts upper level se consistent hone chahiye.
4. Consensus lock hone par S3 (MRP), S4 (MPS) aur S5 (DRP) ko publish hota hai, aur Finance ko revenue forecast jata hai.
5. ATP = on-hand + scheduled receipts - allocated/committed (time-phased). CTP MPS ki unallocated capacity aur material se nikalta hai.
6. Tracking signal threshold cross hone par auto alert aur re-forecast job.
7. Champion-challenger: naya model sirf tab champion bane jab hold-out accuracy better ho aur approval mile.
8. AI forecast changes `ai_decisions` mein, auto-apply limit config se.

### APIs
```
POST /api/scm/lastmile/requests    GET/POST/PUT .../customers/:id/profile    GET/POST/PUT .../addresses    POST .../addresses/validate
POST /api/scm/lastmile/orders    GET/PUT .../orders/:id    GET .../orders/:id/track
GET/POST/PUT /api/scm/lastmile/resource-plans    GET/PUT .../zones    GET .../slots?zone=X&date=Y    POST .../slots/reserve
POST /api/scm/lastmile/routes/optimize    PUT .../routes/:id/assign    POST .../routes/reoptimize    GET .../dispatch/live
POST /api/scm/lastmile/driver/stops/:id/arrive|attempt|complete    GET .../driver/my-route    POST .../cod/reconcile
GET/PUT .../exceptions    GET .../failures    POST .../orders/:id/reschedule
POST .../feedback/request    POST .../feedback    GET .../feedback/analytics    POST .../driver-coaching
```
### Core Logic
1. Address geocode confidence low ho to validation prompt (pin drop) before dispatch, aur galat address se failed attempt kam.
2. Slot availability = zone capacity - booked, aur surge/priority slot pricing config se. Checkout ko real-time dikhta hai.
3. Resource plan = forecast orders / (stops per route target) = drivers needed, aur gig capacity buffer.
4. Dynamic routing: time windows, vehicle capacity, driver hours, traffic, aur live new orders/cancellations pe re-optimize (rate-limited, driver ko minimal disturbance).
5. Driver app offline-first, scan-confirm, geofence-verified arrival, aur e-POD (photo/signature/OTP, tamper-proof timestamp) chargeback disputes ke liye evidence.
6. Customer ETA live, ETA shift threshold par proactive notification aur one-tap reschedule/leave-safe/neighbor options.
7. Failed attempt par auto-flow: reason code → re-attempt slot offer → N attempts ke baad return-to-depot (S18 returns).
8. COD reconciliation per driver per day, variance threshold par alert.
9. Feedback trigger rules: delivered orders ka sample, failed/late orders ka 100%. Detractor/low CSAT par ticket + recovery, aur driver-wise trend se coaching.
10. Last-mile cost per stop, first-attempt success %, on-time %, aur emissions per drop KPIs dashboard mein, aur EV routing/range aur emission reporting.
11. Customer consent aur data retention (privacy law) `lm_customer_profiles.consent_json` se enforce.
