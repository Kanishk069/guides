Pehle research karta hu ki badi companies mein ye kaam asal mein kaise hota hai, phir Batch 1 deta hu.# IT MANAGEMENT PLATFORM: ENTERPRISE GUIDE v2, BATCH 1 (Screens 1-8, Modules 1-4)

**Kaise padhna hai:** Jo line bina tag ke hai wo tere current guide se **as it is** hai. Jo **ADD** se shuru hota hai wo naya hai. Maine kuch bhi delete nahi kiya.

**Research basis:**
- **Demand intake:** ServiceNow SPM mein demand intake stage gates ke saath hota hai (structured demand intake with stage gates aligns to enterprise PMO governance). Idea ko formal demand mein promote kiya jaata hai (ideas can be submitted, developed and promoted to a formal demand request). Demand ke saath cost, risk aur capacity assess hoti hai (demand managers assess business cases and capacity, estimate costs, evaluate risks).
- **SLA engine:** Enterprise SLA mein 6 conditions hoti hain: start, cancel, pause, resume, stop, reset. Retroactive start bhi hota hai, jisme SLA ka start time task ke kisi date/time field se aata hai.
- **Catalog:** ITIL 4 mein service catalog mein ek service ke saath ek SLA link hona best practice hai.
- **TBM Taxonomy:** TBM mein 4 layers hain: Cost Pools, Resource Towers, Solutions, Consumers. Allocation ke methods direct, fixed, shared services, weighted hote hain.
- **TIME:** TIME model Business Value aur Technical Fit ke basis par 4 strategies (Tolerate, Invest, Migrate, Eliminate) deta hai.
- **Finance gap:** SPM tools mein ek common complaint hai ki finance capabilities project features se kamzor hain. Isliye Module 2 aur 4 mein finance depth extra rakhi hai.

Baaki points (health score, burn-rate alerts, survey throttling, constrained prioritization) mere enterprise-practice knowledge se hain, in par maine web search nahi kiya.

### Core Logic
1. Applicability rules (entity, country, data type) se pata chalta hai kaun si regulation kis system pe lagu.
2. Residual = inherent minus control effectiveness (Module 8 se auto).
3. Risk score config matrix se; FAIR mode mein loss-range Monte Carlo (config simulation count).
4. Appetite breach par risk auto-escalate to owner + risk committee.
5. Framework crosswalk: ek control ek baar test, multiple frameworks mein credit.
6. Resiliency gap = required RTO/RPO vs actual (DR test results Module 9); gap par risk auto-create.
7. `audit_log`.
8. ADD: Regulatory change event aane par: impacted obligations to controls to policies to systems nikal ke tasks (owner + due) auto-create; sign-off ke baad hi change "closed".
9. ADD: FAIR run: har input distribution (PERT/triangular) se sample, N trials, outputs ALE/P50/P90/P95 + curve store; simulation ke saath model_version + input snapshot save (reproducible).
10. ADD: FAIR input mein assumption bina source/evidence ke save na ho (config), calibration date purani ho to "stale assumption" flag.
11. ADD: Control add/improve ka what-if: control effectiveness se frequency/magnitude adjust karke naya curve; ALE delta se treatment ROI = (ALE reduction - cost) / cost.
12. ADD: Appetite utilization = current aggregate exposure / appetite limit; >= 80% par warning, >= 100% par breach workflow.
13. ADD: Risk acceptance authority: $ exposure ke hisaab se approver level (BU head, CISO, risk committee, board); acceptance expiry par risk dobara "open" aur owner ko task.
14. ADD: Vendor concentration: ek vendor/region par critical services ka % threshold cross kare to risk auto-create; vendor residual score gire to due diligence re-assessment trigger.
15. ADD: Cyber insurance: policy limit < P90 loss ho to "coverage gap" flag; renewal 120/90/60 din reminders.
16. ADD: Framework profile score auto: control test results se requirement status; Target tier vs Current tier gap par action item (owner, due) auto-draft.
17. ADD: SPOF detect: CMDB graph mein koi CI jisse N+ critical services depend karein aur redundancy na ho; ya sab nodes ek AZ mein.
18. ADD: RTO realism: dependency recovery chain ke runbook step timings sum karke estimated RTO vs required; zyada ho to gap auto-create (Module 9).
19. ADD: Resilience recommendation: service tier ke liye mandatory pattern set vs current pattern; gap par recommendation + project draft (Module 4 proposal).
20. ADD: OT zone ka achieved SL < target SL ho to risk register entry + safety-impact zone ke liye priority high.

### Core Logic

**Research basis (web search se):**
- **CMDB:** CMDB health teen cheezon se naapi jaati hai: completeness (required attributes bhare hain ya nahi), compliance (CIs desired-state audit pass karte hain ya nahi) aur correctness (duplicates, orphans, aur staleness jo aam taur par 60 din ke window ke baad flag hoti hai). Mature organizations 90%+ completeness aur correctness, 2% se kam duplicate rate aur 90%+ relationship coverage ka target rakhte hain. Identification and Reconciliation Engine (IRE) decide karta hai ki incoming data kisi existing CI ko update karega ya naya CI banayega. Har data source ke liye reconciliation rules chahiye taaki kam reliable source authoritative source ko overwrite na kare. Integrations ka data IRE se tabhi guzarta hai jab service-graph-connector style method use ho, isliye maine integrations ko IRE ke through hi route kiya hai. Kharab CMDB data change impact analysis, incident response aur audit readiness ko kamzor karta hai, isliye CMDB trust score ko Module 14 ke impact analysis se jod diya hai.
- **ITAM/SAM:** Effective License Position (ELP) entitlements (jo kharida) ko actual installed/used se compare karta hai. ISO/IEC 19770-1:2017 ITAM ka international standard hai, aur vendor metrics (Oracle, Microsoft, IBM PVU/ILMT) tool ko normalize karne aane chahiye. Useful KPIs: vendor-wise ELP, software spend aur realized savings, % licenses actually used, reclaimed licenses, audit exposure aur renewal accuracy. Ek industry estimate ke hisaab se mature SAM ke bina organizations 20-30% software over-spend karte hain, aur SaaS management alag discipline hai kyunki spend ab zyada SaaS subscriptions par hai. Manual ELP report mein mahine lag sakte hain, aur audit request ko ignore nahi karna chahiye. Unseen installations license counts bigaad dete hain, isliye discovery coverage ko license position se jod diya hai.
- **Major incident/SRE:** Incident Commander (IC) response ka single authority hota hai, aur IC ek dedicated communication channel banata hai. IC ka sabse zaroori kaam ek living incident document maintain karna hai, aur postmortem completion rate track hona chahiye. Status updates ki cadence severity ke hisaab se hoti hai (jaise SEV2 par har 1-2 ghante), status page se "is it down?" queries kam hoti hain, aur postmortem blameless hona chahiye.
- **Support staffing:** Erlang C ko paanch inputs chahiye: volume per interval, average handle time, service-level target, maximum occupancy aur shrinkage. Scheduled agents = N / (1 - shrinkage), aur shrinkage aam taur par 20-35% hoti hai. Erlang model required agents ko zyada bata sakta hai, aur multi-skill environment ke liye WFM system chahiye.
