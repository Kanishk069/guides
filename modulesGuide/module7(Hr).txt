# COMMON FOUNDATION (sab modules pe lagu)

**Common rules:** API prefix `/api/hr/...`. Har create/edit/action `audit_log` mein jayega. Har master `effective_from/effective_to` aur `status[draft/active/disabled]` ke saath hoga (delete nahi, disable). Har table mein `entity_id` hoga (multi-company). Policy, rate, limit aur timeline **config tables** mein rahenge, hardcode nahi.

**Shared tables:**
```

approval_workflows (id, module, condition_json, steps_json[role/user, order, sla_hours], status)
approval_requests (id, module, record_id, requested_by, current_step, status[pending/approved/rejected/withdrawn], created_at)
approval_actions (id, request_id, step, actor_id, action, remarks, acted_at)
```

**(NEW) Common rules add:**
- **Effective-dating:** job/org/grade/location/manager changes `employee_assignments` mein effective-dated. Past, current aur future dated records ek saath dikhte hain, aur "as-of date" se koi bhi report chalti hai.
- **Approval Engine upgrade:** parallel steps, conditional steps, send-back, rescind, delegation/proxy, escalation on SLA breach, aur approver na mile to fallback role.
- **Multi-country:** amount fields ke saath currency code, aur reports mein base-currency conversion.
- **Multi-language:** user-facing text (policy, JD, letters, forms) `translations` se.
- **Reference data:** reason codes aur masters config se, hardcode nahi.

**Dependencies (naam se):** Employee Master, Approval Engine, Notification Engine, Document Store, ESS Portal, Ledger, Time & Attendance, Payroll, Analytics.

### Core Logic
1. Har Strategic Need ek ya zyada Objective se link hoga, aur har Objective ek HR Measure se, taaki need se result tak traceability rahe.
2. RACI versioned hai. Publish karne par purana version `effective_to` ho jata hai aur Approval Engine se approval chalta hai.
3. HR Measures ki values auto-pull ho sakti hain (attrition, time-to-hire, cost per hire Analytics se), warna manual entry.
4. HR Cost: actuals Ledger se aate hain. Cost per employee = total HR cost / active headcount.
5. Objective RAG auto hota hai: actual >= target Green, 80-99% Amber, <80% Red. (NEW: ye limits `hr_measure_thresholds` se config hongi, 80% sirf default)
6. Review "Revise Plan" karne par objectives ka naya version banta hai aur purana history mein rehta hai.
7. Stakeholder Update publish hone par audience ko notification jata hai aur `read_count` track hota hai.
8. Har change `audit_log` mein.
9. (NEW) Parent objective ka score child objectives ke weighted average se roll-up hota hai.
10. (NEW) Multi-currency costs group base currency mein `exchange_rates` (budget rate) se convert hoti hain.
11. (NEW) Contract end se 90 din pehle tech-inventory renewal reminder.

3. Plan submit hone par Approval Engine chalta hai. Approved plan ka `wfp_plan_lines` Recruitment ke Staffing Plan (**Module 8**) ko feed karta hai. (FIX: pehle "Module 4" likha tha)

6. "Adjust Plan" naya version banata hai aur reason mandatory hai.
7. Model formulas safe-eval hote hain (restricted variables), versioned, aur har run ka input/output `wfp_model_runs` mein save hota hai.
8. `audit_log` har action pe.
9. (NEW) Position cost = `wfp_cost_rates` se fully-loaded cost, aur plan cost = sum(position cost x FTE x months) base currency mein.
10. (NEW) Approved plan baseline lock hota hai. Baseline vs latest forecast alag track hote hain.
11. (NEW) Active hiring freeze mein requisition create hone par warning ya block (config), exception approval ke saath.
12. (NEW) Plan approval mein Finance + HR + BU Head, plan cost threshold ke hisaab se levels badhte hain.
13. (NEW) Transition matrix se internal promotions/moves ka supply par asar calc hota hai.

### Core Logic
1. Run engine: Structure (condition then formula then fixed) + Attendance (LOP) + OT + Additional Salary + Arrears - Advance/Loan EMI - PF/ESI/PT/LWF - TDS = Net. Components structure order mein evaluate, formula safe-eval.
2. Regime = employee assignment mein linked Income Tax Slab. Monthly TDS = (annual tax - tax deducted till date) / remaining sub-periods. Exemption flag: proof vs declaration.
3. Single feed: bonus, incentive, referral, retention, claims, leave encashment, recognition awards sab Additional Salary se.
4. Run Completed → Ledger JE. Approved → bank batch eligible. Batch Paid → run Paid → slips auto-generate.
5. Bank: tool bank-compatible file banata hai (config-driven column mapping), maker-checker, IFSC/duplicate/zero validations, withheld employees auto-exclude, response CSV se UTR reconcile, failed ka retry batch.
6. Statutory rates/slabs/limits/due dates sab config tables mein (effective-dated). LWF/PT employee ke `work_state` se, PF/ESI entity code se.
7. Remittance due date par reminder, overdue par escalation, "Mark Remitted" par Ledger liability clear.
8. Submitted slip/slab/run immutable, correction sirf Arrear/Correction se.
9. Gratuity: 15/26 x last wages x completed years (6 months+ round up), eligibility aur cap config se.
10. Entity-wise isolation: ek run mein ek hi entity.
11. `audit_log` har action pe, bank/PII fields encrypted aur masked.
12. (NEW) **Wage definition:** `counts_as_wage` components ka total aur excluded components ka total compute hota hai. Excluded total remuneration ke config % (Labour Codes mein 50%) se zyada ho to excess "wages" mein add-back hota hai, aur wahi wage base PF, ESI, gratuity, bonus, leave encashment, retrenchment compensation, maternity benefit ke calc mein use hota hai. Structure save/publish par validator chalta hai.
13. (NEW) **Pay group aur calendar:** employee ka run uske pay group ke calendar ki period/cut-off se hota hai. Cut-off ke baad aaye changes agle period mein retro adjustment banate hain, current run mein nahi.
14. (NEW) **Run flow:** checklist pass → simulation (optional) → live run → exception report → multi-level approval → GL posting → bank batch → slips. Variance threshold cross hone par next approval level mandatory.
15. (NEW) **Retro engine:** effective date purani hone par affected periods detect hote hain, har period ke liye component-wise recompute hota hai, delta (aur statutory/tax effect) current period mein arrear lines ke roop mein jata hai, aur original runs immutable rehte hain.
16. (NEW) **Trace:** har run item ke liye component-wise calculation trace save hota hai (input, formula, result), jisse payroll query aur audit mein "yeh number kyun" turant explain hota hai.
17. (NEW) **Parallel run:** legacy output upload karke employee/component-wise variance nikalta hai, aur cutover se pehle accepted-variance sign-off.
18. (NEW) **Deductions:** total deductions statutory cap/net-pay protection (country rule) ke andar rehte hain. Priority order: statutory → court/legal orders → loans/advances → voluntary. Cap se zyada hone par lower-priority deduction defer hoti hai aur carry-forward track hoti hai.
19. (NEW) **Final wages:** exit par wages-linked dues (basic, DA, wage-linked components) `final_wages_due_working_days` ke andar pay hone ke liye off-cycle run schedule hoti hai, baaki dues (asset recovery, gratuity timeline wagera) `other_dues_due_days` ke hisaab se. Dono deadlines alag track hote hain, aur clearance pending hone se wages ka payment block nahi hota (Module 33 ke saath).
20. (NEW) **Tax Year aur forms:** TDS calc, certificate aur return ke form/section code `statutory_form_registry` se (tax year ke hisaab se) aate hain. FY 2025-26 aur usse purane periods ke liye purane forms, Tax Year 2026-27 se naye. Kisi form number ko code mein hardcode nahi karna.
21. (NEW) **TDS inputs:** previous-employer income, perquisites (ESOP, loan, car), regime declaration aur proofs sab monthly projection mein jaate hain. Regime change window ke baad lock, aur year-end shortfall/excess adjustment last periods mein.
22. (NEW) **PF trust:** exempted trust entity ke liye contributions trust ledger mein, interest rate trust declare karta hai, aur member balance statement trust ledger se. EPFO-covered entities ke liye ECR flow alag.
23. (NEW) **Gratuity:** eligible service threshold (permanent 5 saal, fixed-term 1 saal pro-rata: config), wage base upar wali wage definition se, accrual monthly provision (Module 28 GL accrual), aur funding/valuation export.
24. (NEW) **Bank controls:** bank account change par verification + cooling period. Payroll cut-off ke paas aaye change par payment hold aur dual approval. Duplicate account (alag employees, same account) auto flag.
25. (NEW) **Payment formats:** `payment_formats` registry se (ISO 20022, NACHA, BACS, SEPA, WPS, NEFT/RTGS bulk, CSV). Split payments priority order se, aur format-specific validations (IBAN/IFSC/sort code).
26. (NEW) **Bank response:** response file se payment-level status (accepted/rejected/returned) update, rejected ka retry batch, aur 30/60/90 din se unreclaimed/returned payments `unclaimed_wages` mein.
27. (NEW) **GL:** run completed par cost-center/allocation split ke saath journal, multi-currency conversion run-date rate se, aur accrual/reversal entries. ERP export format config se.
28. (NEW) **Reconciliations:** gross-to-net, headcount (HRMS vs payroll), GL, bank aur statutory recon har run ke baad auto-run, aur unresolved variance par payroll sign-off block.
29. (NEW) **Segregation of duties:** input entry, calculation, approval aur payment release alag roles; ek user dono step nahi kar sakta (config).
30. (NEW) **External payroll:** jin countries ka payroll outsourced hai wahan inputs export, results import (net/gross/tax/payslip/GL), aur import ke baad wahi recon/GL/payslip flow.

### Core Logic
1. Retirement list DOB + retirement age rule (config), 6 months pehle notification, extension approval.
2. LOA payroll treatment: unpaid → LOP; paid → normal; partial % config. Leave balances/maternity statutory limits config se. Return date par employee status active.
3. Exit: LWD par F&F due = LWD + configurable working days (statutory wage-payment timeline, config), gratuity alag timeline config se.
4. F&F ek off-cycle payroll run: pending salary + leave encashment + pro-rata bonus + claims - notice shortfall - loans - asset recovery - TDS true-up. Gratuity alag line. Negative net par "recoverable" flag.
5. Pending clearance par approve/pay block (HR override with reason).
6. Training bond/recovery, benefits end (Module 25), flight-risk/exit themes analytics (Module 24) ko feed.
7. Approval, then Bank batch (Module 31), Paid par employee `exited`, ESS limited access.
8. Cancel (withdrawn) par employee active, paid hone par block.
9. Termination discipline case se link (Module 21).
10. `audit_log`, sensitive amounts access log.
11. (NEW) **Wage vs other dues:** F&F ke do deadline hain: wages-linked dues `final_wages_due_working_days` (Module 28 settings) ke andar, baaki dues (asset recovery, gratuity, other) `other_dues_due_days` ke andar. Clearance pending hone se wage payment block nahi hota (sirf other dues/relieving documents). Dono deadlines miss hone par alag escalation.
12. (NEW) **Termination risk check:** initiate hote hi employee ka status check hota hai (LOA, open grievance/whistleblower, union representative, recent protected action). Flag hone par Legal approval ke bina termination/redundancy approve nahi hota.
13. (NEW) **Notice:** notice period = policy (grade/country) se. Buyout amount = remaining notice days x daily rate (employee-side recovery ya employer-side pay), garden leave mein access/duties rok kar salary chalti hai, aur waiver approval ke saath.
14. (NEW) **Severance:** final = max(company policy formula, statutory floor) cap ke andar (Module 6 simulator wahi engine), aur release agreement sign hone ke baad hi ex-gratia release (config).
15. (NEW) **Leave encashment:** balance (carry-forward cap aur encashment rule config se) x daily rate, wage definition Module 28 se. Fixed-term gratuity pro-rata eligibility Module 30 se.
16. (NEW) **Mass separation:** threshold check establishment ke workers count se (default 300, config). Threshold se upar permission application retrenchment se 60 din (layoff 15, closure 90) pehle, notice period (threshold ke hisaab se), aur Module 20 `ir_statutory_notices` mein entries. Permission mile bina program `approved` nahi hota.
17. (NEW) **Retrenchment compensation** = 15 din ki average pay x completed years (6 mahine se zyada ka part count: config). **Re-skilling fund** = last-drawn wages ke 15 din, retrenchment ke 10 din ke andar deposit, aur worker ko credit status track. Fixed-term contract end retrenchment nahi mana jata (config).
18. (NEW) **Selection:** seniority list (last-come-first-go) category-wise, deviation par reason aur Legal approval, aur fairness check (Module 5 adverse impact) sab selected groups par.
19. (NEW) **Re-employment:** retrenched workers ko re-employment opportunity offers (jab nayi vacancy Module 8 mein khule), aur response track.
20. (NEW) **Deprovisioning:** LWD par IT/access tasks auto-create (ITSM ticket), aur LWD par pending task escalation. Assets recovery Module 13 provisioning records se auto-list.
21. (NEW) **LOA:** statutory LOA type ke rules se paid/unpaid/% aur max duration, aur overlap (maternity + sick) detect. Return date miss par escalation, aur job-protection window ke andar termination block.
22. (NEW) **Death in service:** exit auto-initiate, nominee-wise settlement (gratuity, PF, insurance, pending dues), aur Module 25 insurance claim trigger.
23. (NEW) **PF/Tax exit:** final PF/ESI/PT aur TDS true-up, tax certificate delivery, aur UAN exit-date update task.
